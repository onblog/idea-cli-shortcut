# IDEA CLI 快捷执行插件设计

## 目标

开发一个简单的 IntelliJ IDEA 插件。安装插件后，IDEA 右上角工具栏固定显示一个图标按钮。用户点击按钮后，插件会打开或聚焦 IDEA 内置终端，并自动执行用户配置好的 shell 脚本。

这个插件的定位很简单：作为常用 CLI 命令的快捷入口，减少用户反复打开终端、手动输入命令的操作。

## 技术方案

- 开发语言：Java。
- 构建工具：Gradle，使用 IntelliJ Platform Gradle Plugin。
- 目标 IDE：兼容 IntelliJ IDEA Community。
- 设置页面：使用 IntelliJ Platform 的 Swing 配置页。
- 配置存储：使用 IntelliJ 的 `PersistentStateComponent`。
- 图标资源：使用 SVG，包括插件图标和工具栏按钮图标。

## 用户体验

插件安装后，IDEA 顶部工具栏显示一个小图标按钮。用户点击按钮后，插件读取当前已启用的脚本列表，并按配置顺序执行。

默认配置包含一个已启用脚本：

```bash
echo "CLI Shortcut: configure scripts in Settings | Tools | CLI Shortcut"
```

插件设置页面位于 `Settings | Tools | CLI Shortcut`。设置页提供一个脚本表格，用户可以：

- 启用或停用单个脚本。
- 编辑脚本显示名称。
- 编辑 shell 命令或多行脚本内容。
- 新增和删除脚本。
- 上移和下移脚本，以控制执行顺序。

第一版只做最核心能力：执行时只运行已勾选的脚本，并按表格顺序串行发送到终端。暂不做定时执行、后台任务编排、输出解析、命令模板、项目级脚本配置等功能。

## 架构设计

插件拆成四个小模块：

- `CliShortcutSettingsState`：负责保存脚本配置，并提供默认配置。
- `CliScript`：表示单条脚本，包含启用状态、名称和脚本内容。
- `CliShortcutConfigurable`：设置页面，使用 Swing 表格编辑脚本配置。
- `RunScriptsAction`：工具栏按钮动作，读取已启用脚本，打开终端，并按顺序发送命令。

`RunScriptsAction` 只依赖配置状态和终端 API。设置页面只依赖配置模型。脚本筛选和排序逻辑保持为普通 Java 逻辑，方便在不启动完整 IDE 的情况下做单元测试。

## 执行流程

用户点击工具栏按钮时：

1. 从持久化配置中读取脚本列表。
2. 过滤出已启用且内容非空的脚本。
3. 保持用户配置的脚本顺序。
4. 打开或聚焦当前项目的 IDEA 终端。
5. 将脚本内容逐条发送到终端，每条命令后追加换行。

这个方案把实际命令执行交给终端和 shell 处理。环境变量、当前目录、命令输出、错误信息都直接展示在终端里，用户可以按日常使用终端的方式观察结果。

## 错误处理

如果当前没有可用项目，插件显示一条简短通知，然后不执行任何操作。

如果没有已启用且内容非空的脚本，插件显示通知，提示用户到设置页启用或配置脚本。

如果终端创建失败，插件显示错误通知，并包含失败原因。

插件第一版不检测每条 shell 命令是否执行成功。它只负责按顺序把脚本发送到终端，命令是否成功由 shell 输出体现。

## 测试方案

自动化测试覆盖不依赖完整 IDE 的逻辑：

- 默认配置包含说明用的 echo 脚本。
- 筛选脚本时跳过停用脚本和空脚本。
- 脚本执行顺序保持用户配置顺序。
- 配置状态可以复制和修改，不丢失字段。

手动验证覆盖真实 IDE 行为：

- `runIde` 可以启动沙箱 IDEA。
- 工具栏图标正常显示。
- 点击图标会打开终端。
- 默认 echo 命令可以执行。
- 多个已启用脚本会按顺序发送到终端。
- 未勾选脚本不会执行。
- 修改设置后，重启 IDE 仍能保留配置。

## 暂不支持的功能

- 按项目区分不同脚本配置。
- 为每个脚本单独选择工作目录。
- 并行执行脚本。
- 等待上一条命令完成后再发送下一条命令。
- 捕获或解析终端输出。
- 远程执行命令。
